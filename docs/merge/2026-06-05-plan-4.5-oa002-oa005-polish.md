## Objective

Land two detector-level fixes found during Sonu's review of Plans 3-4, before Plan 5 ships to origin. Both bugs propagate into Plan 4's `--fix` surface and would produce false-success audit-log entries on real projects in Plan 6 dogfood.

## Tasks

### Task 1: OA002 npm: protocol allow-list

Add `npm:` to the prefix-skip list at `src/overrides/detectors/oa002-floating-tag.ts:18` so `npm:lodash@4.17.21` and similar alias redirects are not flagged as floating tags. The line currently reads:

```ts
if (v.startsWith('workspace:') || v.startsWith('file:') || v.startsWith('link:')) continue;
```

Add `|| v.startsWith('npm:')`. Add one test case to the OA002 suite asserting zero findings on `{ overrides: { lodash: "npm:lodash@4.17.21" } }`. Closes #25.

### Task 2: OA005 suggest findings emit fix: undefined

In `src/overrides/detectors/oa005-nested-ineffective.ts`, change the `findingBase` factory so when `action === "suggest"` (OA005.d, OA005.e), the resulting finding has `fix: undefined` rather than `fix: { type: "rfc6902", patch: [] }`. The runnableCommand field disappears with the fix object - that is correct, because there is nothing for the user to "run" on a suggest finding.

Update existing OA005 tests to reflect the new shape: assertions like `expect(f.fix?.patch).toEqual([])` become `expect(f.fix).toBeUndefined()`. Confirm no Plan 4 caller assumes a fix is always present on OA005 findings (search `runOverrides` and `runOverridesFixHook` for OA005-specific branches).

Closes #26.

### Task 3: Plan 4.5 sanity test

Add `tests/sanity/plan-4.5-detector-polish.test.ts` covering:

1. OA002 against an npm: alias project produces zero findings (regression guard for #25)
2. OA005.e suggest finding has fix === undefined (regression guard for #26)
3. Plan 4 dogfood matrix counts unchanged: Ghost = 5, Prisma = 1, Storybook = 7, bun-simple = 0
